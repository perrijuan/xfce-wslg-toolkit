# Windows integration

Run `Setup-Windows.ps1` from Windows PowerShell 5.1 without elevation. The
installer copies `clipboard-host.ps1` and `Focus-Xfce.ps1` into
`$env:LOCALAPPDATA\XfceWSLToolkit` by default and merges the current user's
`.wslgconfig`. No credentials, ProgramData writes, or automatic WSL restart
are used. Existing changed files receive adjacent `.bak-<timestamp>-<id>`
backups before replacement. Unchanged files are not rewritten or backed up.

```powershell
.\windows\Setup-Windows.ps1 -WhatIf
.\windows\Setup-Windows.ps1 -RefreshRate 144
.\windows\Setup-Windows.ps1 -CreateShortcut -Distro 'Example Distro' -LinuxUser example -LinuxLauncher '/home/example/.local/bin/xfce-wsl'
```

`-RefreshRate` accepts 1 through 144, inclusive. The setting is a WSLg
presentation target, not a guarantee of application FPS or physical monitor
refresh. Any required WSL restart must be initiated separately by the user.
INI comments generated by this installer use `;`, not `#`. Existing unrelated
sections, settings, and comments are preserved.

The optional `Xfce WSL.lnk` targets `wsl.exe` directly with explicit
`--distribution`, `--user`, and `--exec` arguments. `-Distro`, `-LinuxUser`, and
`-LinuxLauncher` are all required when `-CreateShortcut` is selected. The
launcher must be an absolute Linux path: expand `~` on the Linux side before
passing it to PowerShell. There is no shell expansion inside the shortcut.
Normal installs use the current Windows user's resolved Desktop directory.

`-TargetDirectory` and `-UserProfilePath` support isolated installs/tests.
When `-UserProfilePath` is explicitly supplied, the optional shortcut goes
under that profile's `Desktop` subdirectory, never the live resolved Desktop.
The clipboard helper must be invoked using Windows PowerShell with `-STA`;
its existing JSON pipe protocol is unchanged and clipboard text is not logged.
The focus helper matches titles starting with `Xfce WSL` only in `msrdc`.

## JSON output contract

Successful invocations emit one compact UTF-8 JSON object, including during
`-WhatIf`. No informational/WhatIf host text is mixed into stdout.

- `windows_helper_dir`: absolute native Windows helper directory.
- `powershell_windows`: absolute native Windows PowerShell executable path.
- `changed`: at least one file differs from the requested state (planned change).
- `applied`: at least one planned change was actually written.

First install normally returns `changed: true, applied: true`; an unchanged
rerun returns both false; a dry run with differences returns
`changed: true, applied: false`. Errors terminate without a success object.
Writes are guarded with `SupportsShouldProcess`; declined confirmations do
not apply the affected file. A failure after an earlier file was written is
not a transaction rollback; adjacent backups preserve replaced data.

## Tests

From the project root:

```powershell
powershell.exe -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -File tests/windows/Test-Setup-Windows.ps1
```

No Pester dependency. Tests create scratch helpers, profiles, INI files, and
shortcuts below `tests/windows/.scratch-<id>`, then remove them in `finally`.
The default-path test temporarily overrides the process environment to point
there too. Tests never change the live `.wslgconfig` or Desktop shortcuts,
launch the Xfce session, restart WSL, or access clipboard text.
